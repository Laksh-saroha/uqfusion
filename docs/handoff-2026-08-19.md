## 2. Fitness was computed wrong all session — found, fixed, gated — **VERIFIED**

In Ultralytics 8.4.90, `DetMetrics.fitness` weights are `[0.0, 0.0, 0.0, 1.0]` — **fitness is
mAP50-95 alone**, not the `0.1·mAP50 + 0.9·mAP50-95` blend of older releases. The repo already knew
this (`consolidate_phase1.py:32`, `recover_row.py:18`); `restore_early_stopping` in
`src/uqfusion/uq/train_gaussian.py` contradicted it.

**Why it mattered.** The blend runs ~15% high against a true mAP50-95 scale. On resume the stopper
was seeded with that inflated value, so no later epoch could beat it: `best_epoch` freezes at the
resume point, the run stops exactly `patience` epochs later, and `trainer.best_fitness` is high
enough that **`best.pt` may never be written again**. A run paused near its peak would silently
return whatever checkpoint it held at the pause.

**Blast radius.** No completed run was corrupted — both pauses landed at epochs 1–2, where the
inflated value was still below later real fitness. Luck, not design. Of the 9 runs analysed, the two
formulas pick the same epoch on 8; they differ only on `gauss_ir_pct_seed0` (blend says ep 35, truth
says ep 54) — which was the A/B run.

**Fix + gate.** `train_gaussian.py:99` now uses mAP50-95. Validated against real data: the corrected
function reproduces what Ultralytics' own stopper did on two independent runs (`gauss_ir_pct_seed0`
best 54 → stopped 74; `parity_ir_seed0` best 37 → stopped 57). `scripts/smoke_resume.py` re-run:
**RESUME SMOKE OK**.

**Not affected:** `run_queue.py:361` reads `stopper.best_fitness` from Ultralytics directly rather
than recomputing, so queue state and the dashboard were always right.

## 3. Percentile IR — built, measured, **rejected** — **VERIFIED**

This supersedes `ir-handoff-2026-08.md` §4 (which proposed the change) and §5.1 (whose "zero IR
results to invalidate" timing argument expired the moment Phase 2 ran).

### 3.1 What was built

`Pohang_dataset/infrared_pct/` — 31,010 frames re-exported from the raw 16-bit archive with
**per-frame percentile clipping at 0.5–99.5** (IR-D1), then letterboxed 640×512 → 640×640.
Percentiles are computed on the **unpadded** frame; folding in the 64 pad rows would drag both
bounds toward 114. Script: `scripts/export_ir_percentile.py`.

Labels and split lists are **copied** from the min–max tree, not recomputed — the letterbox geometry
is identical and copying makes that guaranteed. Copies, not hardlinks, so a future label edit (the
§5.2 crossover filter) cannot hit both trees.

**Verification gate (the important one):** the same code path reproduced the *existing min–max
pixels* at **max abs diff 0** across 60 frames spanning the tree. That proves the raw→frame mapping,
uint16 read, scaling and letterbox all match what produced the current tree, so percentile is the
only variable.

Audit: 31,010 images, 31,010 labels, split lists byte-identical, geometry 640×640 uint8, padding
rows confirmed at 114, 0 missing images/labels across train/val/test.

Contrast gain measured: **median 1.49×**, 48% of frames >1.5×, 15% >2×, max 13.08× — matching the
handoff's predicted ~1.5×.

Derived subset: `runs/derived/data_ir_pct_stride2.yaml` (11,640 frames, **identical frame
membership** to `data_ir_stride2.yaml`).

**The raw archive on D: was not touched** — all 96,343 raw IR files scanned, newest mtime
2026-07-05, 44 days before this session. `export_ir_percentile.py` opens D: read-only and
`_assert_safe_out` refuses any write outside the repo.

### 3.2 The A/B result

Both arms: `gauss`, seed 0, identical settings, identical frame membership. Compared at each run's
true `best.pt` epoch.

| | min–max (ep 41) | percentile (ep 54) | Δ |
|---|---:|---:|---:|
| **mAP50-95** | 0.06453 | **0.06566** | **+0.00113 (+1.75%)** |
| mAP50 | 0.16641 | 0.15085 | −0.01556 |
| precision | 0.23567 | 0.22918 | −0.00649 |
| recall | 0.17120 | 0.15544 | −0.01576 |

### 3.3 Decision: dropped

+1.75% on the headline metric for a **1.6-point recall loss** is too thin to adopt. The recall drop
is the predicted failure mode: in a maritime thermal scene the targets *are* the hot outliers, so
clipping the upper tail saturates marginal small/distant contacts.

**Why the effect was always going to be small** (the part worth internalising): min–max and
percentile are **both per-frame affine maps** — same family, different constants. A convnet with
normalisation layers is largely invariant to global affine intensity rescaling, so most of the 1.49×
"contrast gain" is invisible to the model. The genuine differences are finer quantisation of the
scene bulk (percentile better) and information destroyed in the clipped tails (percentile worse),
and they nearly cancel. **No global remapping can fix local contrast** — if a hull sits within
sensor noise of the water behind it, stretching the histogram scales signal and noise together.

**State on disk:** both trees retained. `data_ir.yaml` remains the default; nothing was renamed or
deleted. `parity_ir_pct_seed0` and `_ft` are queued but marked **skipped** in
`runs/queue/control.json` with the reason recorded.

IR-D2 (per-frame vs global) and IR-D3 (keep both) are moot for now — per-frame min–max stands, both
trees kept.

## 4. Why IR sits at 0.065 — diagnosis — **VERIFIED**

Three candidates were named; measurement killed two.

### 4.1 Target size — refuted

| val boxes, at 640 model input | IR | VIS |
|---|---:|---:|
| ship median area | **294 px²** (17.1 px side) | 197 px² (14.0 px side) |
| ship <32² | **81.1%** | 86.9% |
| ship <16² | **45.5%** | 58.3% |
| content rows in the 640 canvas | **512 (80%)** | 338 (53%) |

IR targets are **larger** at model input and IR wastes less canvas on padding. IR is favoured on
every geometric axis and still scores 4× worse. Worse for the hypothesis: VIS is 2048×1080
downscaled by 0.3125 (`resize_walkthrough.md`), so its median ship is ~45 native sensor pixels
squeezed to 14 — and it still wins 4×. IR is shown at full native scale (letterbox scale 1.0, pure
padding).

### 4.2 Buoy imbalance — mostly refuted, one piece **OPEN**

mAP is **macro-averaged over classes**, so 596 buoys count as much as 18,281 ships; instance
imbalance does not mechanically drag the number. VIS has *more* buoys proportionally (7.0% vs 3.2%)
and scores higher, so the direction is wrong.

What imbalance *can* do is collapse buoy AP toward zero. **Per-class AP has never been run** — one
minute against the existing checkpoint, and it decides whether the story is "buoys are invisible in
640×512 thermal" (expected, publishable) or "ship AP is also 0.07" (something is wrong). The single
cheapest open measurement in the project.

### 4.3 Capacity — real but small

Phase 1: `yolo26s` → `yolo26m` on VIS was 0.2864 → 0.3061, ~+7%. Same relative gain on IR moves
0.065 to ~0.070. Not a 4× explanation.

### 4.4 What it actually is

| | mAP50 | mAP50-95 | ratio |
|---|---:|---:|---:|
| IR | 0.1664 | 0.0645 | **0.388** |
| VIS | 0.6553 | 0.2505 | **0.382** |

Essentially identical. **IR localises as well as VIS relative to what it finds** — the entire
deficit is in *detection*, not box placement. This also rules out the thermal-bloom hypothesis
(`ir-handoff` §5.3): noisy IR box extents would be punished disproportionately at high IoU and
depress the ratio. It doesn't.

What remains is **information content per pixel** — target/background separability in a single
thermal channel. That is scope §10's thermal crossover: a vessel near the sea's own temperature
produces almost no signal at any histogram scaling.

**Highest-value next measurement:** quantify the crossover fraction (`ir-handoff` §5.2). Per-box
local contrast (Weber/Michelson, or Sobel at the box perimeter) across IR train;
`filter_night_boxes.py` already has the box-scoring machinery; CPU-only. If 30% of IR boxes sit at
noise level, that *is* the answer, it is publishable, and it converts 0.065 from "disappointing"
into a measured physical limit.

**And the framing that matters:** IR does not have to reach VIS's 0.250. Its job is to beat
**degraded** VIS under fog/glare/darkness. 0.065 against clean VIS is the wrong comparison; the
right one is the Phase 3/4 corruption sweep, still unmeasured.

### 4.5 Lever asymmetry for OQ-11

`imgsz` is a **strong VIS lever and a null IR lever**. VIS has 2048 native pixels currently thrown
away; IR is already at native 640×512, so raising imgsz only upsamples. Cost and benefit therefore
scale differently per modality — do not price them together.

Four clear losses, one within noise. The ft peak epoch also marched earlier as runs went on — 8, 4,
2, 2, 1 — so the stage drifts off the parent almost immediately, faster on IR than VIS. Even the

**Not yet decided, deliberately.** Option C was justified on **σ calibration**, not mAP: training

still hypothetical.

Each stage writes its own `best.pt` and the parent's is untouched, so the ft stage can never damage
anything — it is an extra candidate, not a replacement.

**Decision point:** keep through Phase 3 and judge on calibration, or drop now and reclaim 10 epochs
per run at full scale. **OPEN.**

## 6. §12.1 parity — the sign flips — **VERIFIED**, still **OPEN**

| pair | σ arm | parity arm | Δ (σ − parity) |
|---|---:|---:|---:|
| VIS | 0.25049 | **0.26124** | −0.01075 |
| IR (min–max) | **0.06453** | 0.06069 | +0.00384 |

The σ arm loses on VIS and wins on IR. **A fixed structural penalty would not reverse direction
across datasets**, so this is evidence against "the variance branch costs accuracy" and the
strongest support yet for the floating-point non-associativity hypothesis already on record.

It does **not** establish parity. Magnitudes: IR's gap is smaller absolutely (0.0038 vs 0.0107) but
larger relative to its own scale (6.1% vs 4.2%), and there is one seed per arm, so neither can be
classified as noise or signal.

**Recommendation, unchanged and now better supported:** D17's "bit-identically by construction"
claims more than a single-seed pair can demonstrate. Re-specify §12.1 as a **multi-seed comparison
with a stated tolerance**. `scripts/smoke_parity.py` remains deliberately red.

Caveat to own: `parity_ir_seed0` carries one augmentation-stream discontinuity
(`reseed_at_train_start` re-seeds on every train start, so a resumed run restarts its augmentation
stream) from the pause at epoch 2; `gauss_ir_seed0` ran unpaused.
