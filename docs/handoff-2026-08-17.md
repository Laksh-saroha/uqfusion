## Code changes this session

YOLO26 is `end2end=True`, `reg_max=1` — no DFL, no NMS. `convert_to_gaussian` used to raise
`NotImplementedError` on it. Ported in `src/uqfusion/uq/gaussian.py`:

| change | why it is not optional |
|---|---|
| `_sigma_box_head()` attaches `cv4` to **one2one** on end2end heads | inference decodes from one2one; the branches use different assignments (topk 10 vs 7/topk2 1), so σ on one2many would describe a predictor that never reaches the output |
| `GaussianDetect.postprocess()` gathers σ with the boxes' top-k index | stock splits `[4, nc]` exactly — trailing σ columns get read as class logits and can win the top-k |
| `gaussian_nll` branches on `use_dfl`: μ = raw box output, target **unclamped** | `bbox2dist(..., reg_max-1)` at `reg_max=1` clamps to `(0, -0.01)`; torch returns `max` when `min > max`, collapsing every target to the constant −0.01 |
| `GaussianE2ELoss` adds the NLL **outside** the o2m/o2o schedule | that schedule moves one2one 0.2 → 0.9 over a run; inside it, `nll_gain` and the warm-up would silently stop meaning anything |

`src/uqfusion/uq/infer.py` skips NMS on end2end heads. Both layouts put σ at columns 6:10,
so everything downstream of `det` is shared.

**Known limitation:** `sigma_detach_features=False` cannot be honored on end2end heads
(ultralytics detaches one2one upstream) — forced `True` with a warning. That ablation needs
a plain-`Detect` backbone.

## Two traps for the data prep

1. **`rect=True` silently forces `mosaic=0`** (`ultralytics/data/dataset.py:226`). It looks
   like a free 45% saving on 2048×1080 (letterbox is 47% padding at square `imgsz`) but
   costs mosaic, which the 640 grid used. Recommend square letterbox + mosaic retained.
2. **Pre-resize once instead of shipping native.** Every epoch downscales to `imgsz` anyway.
   Resizing long side → `imgsz` with no padding keeps normalized labels byte-identical
   (aspect preserved), cuts storage ~2.5×, and removes a per-epoch 2048×1080 decode that
   would likely bottleneck the server's `workers=2` (`/dev/shm` cap). Reuse
   `scripts/prepare_pohang_fullres.py`.

If OQ-11 lands on 1280 and you pre-resize (trap 2): VIS drops 84.2 → **33.1 GB**, total
**~51 GB → provision 65 GB**, and epochs get faster.

Reference points and knobs:

- PNG source is 315.6 GB. **Do not ship it.** q95 is 27% of PNG; q90 is 51.9 GB (16%); q85
  is 38.2 GB (12%).
- The **640 dataset does not need to go to the server** — Phase 1 is closed and the §12.1
  parity row will be retrained at the new `imgsz`.
- Cache sizing assumes ~7 KB/frame, dominated by the pooled feature vector (yolo26m neck
  widths 256+512+512 = 1280 floats = 5.1 KB). Corrupted images are generated
  deterministically at cache-build time and never stored.
- Model count: Phase 2 = gaussian VIS + IR, parity VIS + IR (4); Phase 3 = MC VIS + IR (2),
  ensemble M=5 × 2 modalities (10). Option A adds 1; M=3 saves 4; Phase 4 multi-seed adds ~3.

**JPEG caveat, worth one line in methods:** Phase 1 trained on PNG; Phase 2+ would train on
JPEG. Compression artifacts shift pixel statistics feeding the Mahalanobis OOD score (O3)
and interact with the synthetic corruption pipeline. Consistent from Phase 2 onward, so it
confounds only Phase-1-vs-Phase-2 comparisons — which the `imgsz` change already confounds.
